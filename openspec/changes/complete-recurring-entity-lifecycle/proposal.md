## Why

Exomem can detect an unresolved wikilink that recurs, but ordinary history can repeatedly describe a stable identity without ever producing that representation, and an already-created Entity can remain sparse while durable facets accumulate elsewhere. The result is two forms of the same lifecycle failure: the user must nudge the agent both to promote a recurring identity and later to reconnect durable knowledge to it.

## What Changes

- Extend deterministic, corpus-derived entity recurrence evidence beyond unresolved wikilinks to ordinary recurring identities across independent pages, sessions, and Sources.
- Keep the signal type-neutral: people, communities, organisations, places, products, venues, accounts, projects, and vault-defined kinds use the same evidence contract rather than hard-coded per-kind detectors.
- Require evidence that distinguishes stable reusable identities from one-off names, ambiguous labels, temporary participants, and frequency-matched incidental names.
- Project at most one bounded, state-resolved promotion candidate per identity with enough provenance, recurrence, role/membership language, co-occurrence, type cues, and near-match evidence for the active agent to decide.
- Add the sibling hydration path for a resolved existing Entity whose durable facets or canonical pages remain disconnected; surface a guarded update/link proposal instead of a duplicate creation candidate.
- Operationalise optional entity-type parent families for parent-aware filtering and traversal while preserving the singular canonical leaf kind, plural folder projection, and parentless extension compatibility.
- Reuse the shipped vault-extensible entity-type registry and the governed curation lane. Detection remains read-only; the active agent remains the sole semantic decider; type registration and Entity mutation stay inside existing confirmation/delegation rules.
- Contribute the type-neutral recurring-identity, ambiguity-stop, and hydrate-before-duplicate doctrine and fixtures to the single candidate-owned Hosted v5 release; never rewrite Hosted v1-v4.
- Extend the no-nudge benchmark with synthetic positive/negative twins and explicit false-positive measurements. No live-vault names or content enter public artifacts.

## Capabilities

### New Capabilities

- `entity-candidate-curation`: Bounded promotion and hydration candidate lifecycles, evidence payloads, state-change closure, ambiguity handling, and governed hand-off to the active agent and curation executor.

### Modified Capabilities

- `action-first-audit`: Entity recurrence evidence expands from unresolved-wikilink counts to deterministic ordinary-text identity recurrence across independent corpus contexts without silently creating Entities.
- `attention-queue`: Recurring-identity promotion and existing-Entity hydration candidates become bounded, state-resolved active-agent work without entering due-state or creating an autonomous writer.
- `entity-type-registry`: A registered leaf kind's parent family becomes operational for family-aware query and traversal while storage continues to use the leaf kind's own folder projection.
- `agent-bootstrap-contract`: The active agent receives an explicit resolve-before-create and hydrate-before-duplicate decision contract for recurring identities of any registered or proposed kind.
- `portable-agent-contract`: Hookless and skill-enabled agents carry one capability-honest, bounded recurrence-check cadence rather than relying on a topical user request.
- `delegation-envelope`: Candidate surfacing, registry saves, Entity creation or hydration, relation acceptance, and curation execution map explicitly to the existing authority classes.

## Impact

Affected areas include entity recurrence collection and audit projection, attention/review delivery, entity resolution and registry snapshots, parent-aware indexes/query filters, bootstrap and portable-agent guidance, delegation mapping, governed curation work items, the shared Hosted v5 doctrine/fixture composition, the f21 no-nudge benchmark family, synthetic corpora, mutation tests, and compatibility tests for existing core and vault-defined types. `add-governed-curation-lane` is an implementation prerequisite for candidate-to-plan integration. No background LLM, same-modal text generator, confidence float, automatic Entity writer, or universal ontology is introduced.
