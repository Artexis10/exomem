## Why

Current Claude and OpenAI directories distribute Skills with remote MCP. Exomem Cloud already supplies the current runtime, but existing hosted packages still carry separate alpha-era behavioural prose and release controls. One product distribution must carry the current canonical operating contract on both providers.

## What Changes

- Generate Claude and portable OpenAI Cloud packages from the shipped generic scaffold, including all referenced workflow resources.
- Bind packages to current Exomem, the Cloud MCP resource and `product-cloud` capabilities; keep self-hosted Claude Code separate and legacy alpha releases intact.
- Add one shared behavioural corpus and fail-closed cross-surface acceptance/readiness checks.
- Prepare current directory metadata, reviewer cases and release materials; submit the connector and plugin bundles after real-client acceptance and publisher attestations.

## Capabilities

### New Capabilities
- `cloud-plugin-distribution`: deterministic provider packages over one canonical skill source, current Cloud identity and common acceptance evidence.

### Modified Capabilities
None. Existing portable skill and Cloud runtime requirements remain authoritative.

## Impact

Packaging utilities, generated provider packages, CI, shared evaluation fixtures and operator documentation. No new runtime model, auth backend, UI or import path. Model-driven evaluations are client-side instruments, optional until run, and never write runtime doctrine. Missing native evidence blocks readiness rather than being replaced by static tests.
