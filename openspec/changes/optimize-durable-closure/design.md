## Context

The current personal service and repository both identify as 0.71.0. The incident ledger establishes slow server work, not just a connector gap. The existing fast-ACK feature remains default-off. Its receipt/overlay guarantees are already implemented and must survive these changes. Live queues observed after the incident were empty; this does not establish their state during it.

Current ordinary hybrid retrieval admits a maintained lexical snapshot, but optional graph fallback requests an exactly current resolver. A resolver refusal escapes candidate collection and discards all otherwise valid lexical/vector results. Separately, the media command synchronously calls the multi-consumer deferred drain after reconciling an artifact. Neither coupling is necessary for its public semantics.

## Goals / Non-Goals

Measure and reduce the critical path from durable writes to a verified useful result. Preserve canonical ownership, exact pending visibility, policy admission, immutable evidence, and strict relation-filter semantics. No live-vault benchmark writes, deployment, global flag enablement, or new model is part of development acceptance.

## Decisions

1. **Separate optional expansion from mandatory recall proof.** Handle typed resolver-warming outcomes at the optional graph resolver seam in `find.py`/`find_candidates.py`. Omit unproven graph contributions and disclose `graph` as warming. Do not catch catalogue, pending-visibility, governance, structured-filter, or relation-query refusals. Preserve offline fallback. Never call a fallback resolver implicitly after the seam returned unavailable. An old graph snapshot is not served as current.

2. **Media requests own enqueue, not convergence.** Remove synchronous deferred-index draining from `commands._process_media`. Existing fields report zero synchronous refresh and the aggregate global full-upsert count; they do not imply per-item index ownership. The normal background owner retains durable custody. Add a mutually exclusive bounded `paths` selector (1–32 unique canonical governed artifacts), accepted for process/retry only. Reject selector conflicts, invalid shape/bounds and canonical aliases before work; reject paths with status. Execute canonical reconciliation serially under existing per-item guards; expensive extraction already belongs to independent media jobs. Preflight errors are no-work failures; subsequent artifact races/failures are per-item outcomes. Exact full-batch replay uses the existing request digest and returns the same terminal without reconciliation. Retrying a failed subset is a new request with only failed paths, never reusing the original identity with changed arguments. Add a validated compact media projection (at most 32 items): normalized path, closed outcome/state, media type, sidecar path/job id, requeued count, bounded code/remediation. Reject/drop malformed projection by the existing terminal convention; never copy raw errors. Preserve single-path fields. No batch-wide guard or atomic all-or-nothing claim.

3. **Fix amplification at the proven producer/consumer seam.** Reproduce current writer echoes, busy withdrawal, predecessor admission, and long graph drains against disposable state. Known canonical events must advance consumers through exact dirty paths; unknown external edits retain withdrawal-before-clear. A retained complete delta can coalesce intermediate generations only when its source/target and path custody are proven. Missing lineage keeps explicit recovery. Never clear `external_pending` on timeout or weaken byte/policy proof. The implementation must be justified by rerunnable evidence before accepting this task.

   The current reproduction places the watcher event between destination publication and post-commit self-write registration. Repair that window with transaction-scoped publication intents for classic post-commit fanout only; fast-receipt behavior is unchanged. Register staged raw SHA-256 and exact size before replacing destinations. Classify completed proven self events as suppressed, matching active intents as held/undecided, and mismatched or unprovable events as external. Hash a bounded stable descriptor outside the suppression lock. Bind the observation to its token before hashing and retain its final disposition through in-flight adjudication, even when commit removes it from the registry. Re-prove destination bytes at successful registration; an intervening foreign edit is never accepted just because its stat matches.

   Held events remain in the watcher's coalesced custody and schedule deadline wakes. Success drops them only after proven post-commit registration. Abort, failed registration, partial rollback, expiry and capacity eviction actively promote observed paths to external pending and replay them; never silently evict an observation. End-of-transaction failure marks pending before returning, including rollback-incomplete remnants. Overflow or unsupported/unreadable/oversized proof fails open to the existing external path. Expiry must progress without unrelated events, not rely on opportunistic pruning. Tests cover normal publish-before-register, duplicate events, foreign bytes, rollback remnants, registration failure, expiry alone, capacity, and hashing overlapping finalization. The separate appeared-target topology scan under the mutation boundary remains measured follow-up work, not part of this race repair.

4. **Use existing MCP concurrency for generic dependency ordering.** Independent read/media requests can be issued in one agent tool batch; canonical conflicting edits remain ordered. Selected media batching closes a schema gap. Multi-edit already batches edits within a page, and semantic observations/relations can be authored in the initial note. Document a generic client dependency graph and validate it in the benchmark; a second server transaction engine is unnecessary for this repair.

5. **Measure the real public path.** A new benchmark drives registered product commands through a persistent MCP client/server, using disposable isolated state and production managed warm-up. Model-free runs use auto/FTS5 and declare embeddings disabled; graph scheduling and watchers remain active. Seed realistic heterogeneous Markdown, an active tracker, archived related note, critique, a PDF and two images. Preserve/process evidence, update observations and relations, correct a stale edge, then verify direct bytes and search. Model-free proves preservation and durable enqueue/custody only. A separately labelled real-extraction variant must await public completion and assert unique PDF/image content, report extraction engine/dependency versions and convergence, or report blocked/null. Run the optimized workflow with product-required calls and bounded final verification; run a separate stress variant with per-write probes and include them in its full timing/call counts. Probes can trigger repairs or warm caches, so their costs cannot simply be subtracted from the same run. Record successful graph-warming disclosure as optional lag, never as a call-level refusal.

6. **Attribution is additive only where measured.** The ledger provides leaf and server-wrapper durations. Join request identifiers where available. Report its first inferred start to last completion as `ledger_observation_span_ms` and unoccupied intervals as `server_idle_within_observed_span_ms`. Actual workflow wall time/client gaps require a client trace and remain null in ledger-only reports. Compute interval unions separately from summed server work. Model planning and connector overhead remain null unless independently timed. Instrument derived elapsed time, graph incremental/rebuild calls, and source scan counts/bytes in the benchmark. Keep raw personal logs and paths out of published evidence.

7. **Compare a shared functional subset under the existing fairness programme.** The immediate result is an internal diagnostic, not a publishable competitive-suite ranking. Pin Basic Memory 0.23.2's verified wheel digest and resolved dependencies, preserve config provenance/glue accounting/variant identity, and use a warm persistent MCP session for both products with identical Markdown edits, text queries and exact-read assertions. Any adapter fault invalidates its row. Allow native background indexing to converge and measure it separately; do not invoke post-write reindex. Evidence immutability/media are separate capability observations. Publication as a competitive result must follow the existing `add-competitive-benchmark-programme` own-harness/direct-row and independent fairness-review requirements. No internal SQL search substitutes for public APIs.

## Risks / Trade-offs

- Optional graph omission changes ranking during repair: disclose it and never apply the relaxation to graph-dependent predicates.
- A batch can partially commit: validate shared input first and return item outcomes; retry only failed items with stable mutation identity.
- Background convergence can remain slow after fast ACK: benchmark it and gate warming/refusal independently of ACK percentiles.
- Instrumentation adds cost: report configuration and avoid presenting synthetic/model-free timings as full production extraction performance.
- Concurrent machine load affects timing: run performance samples serially after test workers quiesce; retain configuration and timing provenance.

## Migration Plan

Additive media selector and unchanged single-artifact fields require regenerated public tool contracts. Review actual diff and independent reproductions, run the full test corpus once at delivery, then open a ready PR. Production rollout and the existing fast-ACK rollout gates remain explicit. Archive only after merge/shipping evidence and non-optional acceptance are complete.
