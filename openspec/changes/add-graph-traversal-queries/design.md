## Context

This sibling owns graph/ontology contracts from round two of `add-collection-query-engine` (owner items 3 and 6–8, graph portions of 4/9–11). The collection design §§11–15 owns the common IR, agent lifecycle, typed storage/import/rollups, compiler stage and scale tiers. The two changes share one query model, executor and delivery dependency; collection phases can ship before graph readiness without claiming graph delivery.

## Goals / Non-Goals

**Goals:** Match the personal-knowledge graph query tasks available in a dedicated graph tool, add governed epistemic explanations/context integration, and prove latency/task quality on the same invented corpus. Keep the per-vault embedded experience and preserve graph convergence.

**Non-Goals:** Full Cypher text, arbitrary procedures/code, a graph server in this release, cross-vault joins, unrestricted exhaustive walks, billions on SQLite, automatic vocabulary authoring or inferred epistemic authority. Graph algorithms not needed for the specified personal workflows are recorded explicitly in §6, not claimed as delivered parity.

## Decisions

### 1. Existing graph assessment from current source

Reviewed `src/exomem/epistemic_graph.py`, `graph_sync.py`, `traversal_profiles.py`, `relation_registry.py` and `working_set.py` in the round-one worktree baseline. These are implementation evidence, not a new specification authority.

| Current mechanism | What it gives us / actual gap |
| --- | --- |
| `sidecar_path`, `EpistemicGraphIndex._initialize_graph_schema` | Derived `.graph.sqlite` under the external vault state root, SQLite graph_nodes/graph_edges, typed endpoints, semantic unit refs/category/kind, registry version/hash, source author/anchor and review evidence. Already a database, not an in-memory ad hoc edge list. It is separate from the proposed canonical collections store, so no same-transaction row/edge joins today. |
| `neighbors_for`, `relation_participants`, find `relation_of`/`graph_enrich` | Indexed one-hop participants/neighbours; parent relation and replacement roll-up. Ordinary recall has no general path/pattern query surface. |
| `graph_context`, `traversal_profiles.MAX_DEPTH` | An existing Python frontier walker up to **5 hops**, profile node/edge/inspection caps, direction/profile priorities and visible-link resolution. The graph is not universally limited to one hop; the gap is compiled variable-length path queries, shortest/all-path semantics, pattern language and row/page joins. |
| `graph_context(keep=…)`, `_edge_recall_allowed`, `_VisibleLinkView` | Release/exclusion checks before a seed/neighbour/edge endpoint or author becomes a hop; withheld pages must not reconstruct targets. Preserve these semantics in IR admission, including restricted-audience name resolution. This is application governance; SQLite alone does not provide it. |
| semantic source stamps, `_open_read_snapshot`, `_replayed_path_currency`, `graph_sync` checkpoints/epochs and replacement publication | Current projection proof, semantic parent hash/parser version, source dependencies, incremental queue/replay, coherent acknowledgements, single-flight rebuild and atomically proven publication. Withheld/stale/unresolved rows cannot silently become authoritative results. Generic graph storage does not eliminate this convergence work. |
| typed authored `supports`, `contradicts`, `supersedes`, evidence/registry metadata; working-set lifecycle | Epistemic interpretation and provenance, reviewed vocabulary, semantic units and currency compatible with authored supersession. File mtime is not authority. The storage migration must preserve #1453 authored-currency tests; current source alone is not proof every pending currency change has shipped. |

A generic database can store equivalent properties, but does not supply Exomem's per-node/edge release policy, Markdown/semantic-unit convergence, reviewed relation vocabulary, authored-currency selection and context packet compiler as native semantics. Current shortcomings are the limited agent query surface, Python materialization/frontier work, separate edge placement and incomplete transitive ontology identity contract. Recommend **yes: move the edge and vocabulary projection into the per-vault store**, with the migration/freshness conditions in §5. Co-location cannot make file writes transactionally atomic with SQLite; that is the boundary to preserve, not a blocker to indexed joins.

### 2. Structured traversal, paths, patterns and mixed-domain IR

Extend the shared query envelope with `source:{domain:"graph"|"documents"|"collections", ref:…}` and `graph` nodes bound to stable page/unit/item refs. Collection facades retain their type restrictions; `connect_memory(operation="query", query=…)` is the generic graph/mixed entry. Parameters carry refs, typed values and closed operators only. No Cypher, SQL, expression or UDF strings.

Traversal accepts `anchors` (≤8), `min_hops` and `max_hops` (0≤min≤max≤5, default 1..3), `direction:outbound|inbound|any`, `relations` (≤16 stable type refs or resolvable names, subtypes default true), optional entity/category/kind filters and output `nodes|paths`. At min=0 a released seed qualifies. Direction is relative to each step; symmetric relations admit both orientations without inventing a second authored edge. Relations may carry a structured step sequence for a path with changing types/directions. Validate refs/vocabulary before values. No anchor-free graph scan on interactive traversal.

Compile a SQLite recursive CTE over `released_nodes` and `released_edges`. The anchor SELECT is admitted; every recursive term joins an admitted edge, its admitted source/target and admitted author/evidence obligations. Query filters narrow this relation after admission. Bind every user literal; resolve identifiers through the store mapping. A node/edge excluded by release or scope never enters the frontier or the visited-path state. An unknown or withheld anchor yields the same generic not-found result. Withheld nodes/edges break a path, not a post-filtered explanation. A visible shortcut through a withheld intermediary is impossible.

`path:{kind:"shortest", from:…, to:…, max_hops:…}` returns one shortest **unweighted simple path** in the admitted graph, chosen deterministically by stable node/edge-ref tuple among equal lengths. Use breadth-level CTE/frontier evaluation and only declare shortest after exhausting every smaller depth within admitted bounds. If work exhausts bounds before that proof, refuse; no “shortest” label on an incomplete search. `kind:"all", max_hops:k` enumerates all simple paths up to k (no repeated node in a path, directed edge identity retained, parallel authored edges distinct); pagination binds the full query/generation/audience basis. Count results across all paths, not just one page. k=0 returns the released identity path only for identical endpoints. Cycles do not yield infinite walks.

Pattern grammar has ≤8 named node variables and ≤8 edges; each edge names from/to, type/subtypes, direction and 1..5 hop range. One resolved anchor is mandatory. Compile fixed edges as admitted joins and ranged edges as admitted CTEs. Named variables unify stable node identity; explicit `distinct` selects endpoint tuples or paths, not accidental SQL row deduplication. Example: anchor A `-[supports]->` B `<-[contradicts]-` C. Independent reference tests define simple-path and repeated-variable behavior; arbitrary cycles/cross products above budget refuse. Path aggregates support count, distinct endpoints, min/max hop length and grouping by admitted relation/category/kind; exact reductions require completed enumeration. No sum of hidden paths or complete count over a capped sample.

Declared links from row fields to current item/page/unit refs become typed virtual edges in the IR and store projection. Validate target type/collection and same-vault identity, resolve both ends and the declaring collection's release before a hop; no arbitrary join keys. A pattern can start with a released subscription row, follow its declared account page link and then typed `supports` edges. A row update maintains those virtual edges in the same canonical transaction. Relational joins retain the collection change's 2-hop/many-to-one multiplicity contract; graph fan-out has explicit path semantics and cannot silently multiply ordinary grouped SQL results.

Default traversal limits: **5 hops**, **64 released edges per expanded node** (configurable downward; absolute explicit-query maximum 256), **10,000 admitted nodes/50,000 admitted edge visits**, **10,000 path-state expansions**, **1,000 total enumerated paths**, **200 returned nodes/400 returned edges** and the shared **64 KiB serialized result**, **200 ms timeout** and **≤16 MiB additional reader RSS / 64 MiB temp**. Budgets count admitted entities, never hidden degrees. Preview returns separate conservative dimensions: unique admitted nodes may be capped by released node cardinality, and unique edges by released edge cardinality; repeated edge visits and path-state expansions use `anchors × Σ(fanout^h)` over h=1..max plus the applicable pattern/parallel-edge multiplicity. It must not cap repeated visits or path states at distinct graph cardinality, since reconverging simple paths repeat expansion. Charge admission/runtime budgets against repeated work, not just distinct entities. For example, a five-hop layered diamond with 10 nodes/16 edges enumerates 16 paths and performs 46 edge visits. Released degree/selectivity proofs may tighten a bound, but absent such proof it is unknown/conservative and may refuse rather than undercount. Exhausting the runtime cap cannot silently redefine the preview upper bound. Planner graph statistics use the current admitted basis, not global hidden-degree histograms. EXPLAIN verifies `(src,relation,dst)` / `(dst,relation,src)` indexed adjacency and relation-closure lookups. Compiler caps in §4 only tighten this envelope.

Traversal node pages can be explicitly partial with reason/continuation. `all` paths and path aggregates exceeding fan-out/path/state limits refuse `GRAPH_COST_LIMIT` with no complete-looking paths/count; `shortest` refuses if shortestness is not proven. No silent neighbour truncation is called exhaustive. Runtime cancellation uses the shared progress handler; no full-graph Python adjacency list. Physical timeout is operational availability, not a promise of identical microtiming between hidden/absent corpora; semantic budgets, results, counts, continuation and estimates must pass those twins.

### 3. Dynamic ontology in the same governed store

Project current governed Markdown/registry sources into versioned `vocabulary_terms`, `vocabulary_aliases`, `vocabulary_versions` and `vocabulary_closure` tables adjacent to edges. Each term has an immutable internal ID, family (`relation-type|category|entity-kind`), current label/definition, source ref/hash, governed visibility, parent IDs, version and optional replacement/merge identity. The authoritative definitions remain their existing authoring sources; projection does not become a second ontology writer. Open-vocabulary unit categories get a stable term on discovery; they stay usable without mandatory registry registration. Missing authored definition is returned as explicitly undefined, not generated prose. Entity kinds and declared collection types carry current definitions from their registries.

Resolve names/aliases under release, bind queries to stable term IDs and return the current released definition/version with each used dimension. Asking for `supports` includes every subtype recursively (e.g. user `corroborates`, a further `independently_corroborates` subtype); exact-only is explicit. Versioned DAG parent closure forbids subtype cycles. User `is-a`/`part-of` relation instances have distinct transitive graph semantics: traverse bounded admitted instance edges, never use a global closure to bypass withheld intermediaries. Closure answers preserve every path edge as provenance; reaching a cap is partial/refusal, never unbounded logical truth. Declared symmetric/non-transitive type properties are respected.

Renames preserve stable identity and old label aliases. Merges preserve historical IDs and version records, resolve to the current canonical identity and validate/rebind saved views/query-unit fingerprints in the same projection publication. Definition or parent changes advance vocabulary generation and invalidate closure/plans/caches exactly. Removed/ambiguous/semantically incompatible types make a dependent view explicitly unavailable with repair findings; never silently bind it to an unrelated string. Queries use current vocabulary; a saved query with an old rename continues through its stable ID, not an old SQL column label. Edge authored raw label/version remains as history/provenance, while current canonical/subtype interpretation is separately labeled.

For category definitions and rename/merge mappings that do not yet have a canonical writer, add `schema_memory(subject="ontology", operation="diff-ontology"|"save-ontology", proposal={family, term_ref, action:"define|rename|merge", label, definition, replacement_ref}, expected_hash=…)`. These are closed arguments on an existing tool, discovered on demand. Diff returns an immutable current-source proposal/dependency impact; save uses existing schema mutation authorization/confirmation and source-hash guards, writes a versioned governed definition/alias mapping source, and queues projection acknowledgement. Relation/entity-kind changes delegate to their existing family writers and reviewed decisions rather than creating duplicate authority. Registry sources retain stable term refs and replacement history; only the projection is stored beside edges. Ordinary open category authoring via observe_memory remains usable without registering a definition or imposing new confirmation; definition/rename/merge is an explicit governed act. The skill teaches diff→authorized save→query acknowledged version, including unavailable saved views on incompatible merges. These proposed schema operations are not claimed present in today's adapter.

Agents reuse existing vocabulary governance: resolve/reuse or propose through `review_memory(mode="vocabulary")`, record the review decision, author a definition through `schema_memory`/`connect_memory` under existing confirmation requirements. Categories remain open-vocabulary through `observe_memory`; no blanket confirm for ordinary category strings is added. A successful definition write returns its vocabulary version/projection status; the agent can query it immediately if acknowledged, or receives a typed warming result for the requested version. No falsely empty result during propagation, no need for new code per type, no automatic ontology edits to repair a query.

### 4. Relationship explanation and graph-aware activation

A path response includes each ordered admitted node ref/kind/category, edge ref, authored raw and current canonical relation type, definition version, orientation, source page/unit and released evidence refs/source hashes. Include authored date/currency basis and projection/vocabulary generation in private bindings; public output uses release-safe provenance and content hashes. Explain why two things connect by quoting the actual path (e.g. “A supports B; C contradicts B, evidenced by …”), without equating reachability with proof of a claim or transitive `supports` with automatic truth. Missing evidence is marked unavailable; withheld evidence is never cited. An edge whose release depends on evidence cannot enter the path without satisfying that obligation. No invented evidence, confidence or inferred authority.

After collection design §14's anchor resolution, compiler traversal follows authored `supersedes` for currentness, `supports`/`contradicts` for corroboration/conflict and declared cross-collection links. It preserves #1453 authored-currency/lifecycle rules, never mtime freshness or numeric authority. Supersession branches/cycles are explicit ambiguous currency; hidden successors are absent, cannot be named and cannot suppress a visible predecessor through a hidden path. Currency resolution beyond 5 hops abstains with an explicit bounded reason, not an unproven “current” assertion.

Compiler envelope is **≤3 hops, ≤8 released neighbours per node, ≤64 admitted nodes/128 edge visits, ≤2 paths and one request**. It shares the **30 ms stage hard deadline**, with **10 ms graph allocation** inside the collection change's 20 ms allocation; unused time can be borrowed only within 30 ms. Failed graph freshness/admission/cost abstains without withholding an independently fresh row unit. One path-derived unit caps at **2,048 bytes**, stage cap **6,144 bytes**, packet fit/mandatory continuity as in the collection design. Keep ordered path/source/window and actual completeness as “why this is here”; partial graph work cannot authorize an exact path count or a definitive current successor.

Cache depends on query fingerprint, audience/policy, participating collection generation vector, proven graph projection generation and vocabulary version; generation mismatches never reuse results. Bound cache within the shared 8 MiB allowance. Path/query units are reachable and reproducible through MCP query/explain, and activation benchmarks test unit inclusion/provenance gains, negative cases and existing continuity/corpus non-regression.

### 5. Move edge/vocabulary projections without losing convergence

Recommend moving graph nodes/edges, document metadata projection, dependency coverage, parent-ref mapping, graph_meta/replay acknowledgements and vocabulary tables into the one external-canonical per-vault store. Canonical collections/history/audit remain owned by the canonical store; derived graph tables have a separate replaceable projection namespace and generation. No independent live edge database after cutover. Backups include a consistent single-store snapshot; portability re-proves derived file/registry bases before serving them in a new vault lineage.

The current rebuild publishes an entire `.graph.sqlite` file. That must change: replacing the combined database file would destroy canonical collection rows. Build isolated staging projection tables (or a disposable temporary graph build file), stream bounded row copies into the combined store and publish only graph table mappings/checkpoints in one fenced SQLite transaction. Never file-swap/reinitialize the combined canonical store, drop canonical tables or inherit the old sidecar DDL's destructive schema reset behavior. Keep live readers on the old proven graph generation until the new mapping is complete. Bound additional migration memory to ≤64 MiB, report disk high-water and preserve writer fairness. Rebuild/maintenance touches only the replaceable namespace.

For collection links, row write, edge update, collection generation and projection acknowledgement commit together. For knowledge/vocabulary files, existing governed write receipt/checkpoint and durable replay queue span the non-atomic file/SQLite boundary. Enqueue/replay under the actual service writer lease; publish a graph checkpoint only when source/parser/registry hashes, dependency coverage and predecessor/current epoch prove coherence. Crash between file write and projection commit gives warming/unavailable, never stale-complete. Preserve existing poison/quarantine/retry behavior and projection proof after host takeover. A graph-only rebuild cannot alter collection commit_seq/head/audit; a canonical row/link write still advances them normally.

Migration preflight proves store identity/schema/lease, sidecar coherence and source/vocabulary basis; copies projections and replay metadata with row/edge/source parity, installs adjacency indexes, then atomically flips the graph placement capability and coherent generation. Old sidecar stays read-only recovery input until combined-store proof/cutover succeeds, then may be retired by the delivery owner only after a proven backup and no live reader. A failed graph build/cutover keeps the old placement capability and source work queued; collection reads/writes continue. Rollback disables new traversal and serves legacy graph only if its projection still proves current; rebuild legacy sidecar through the service if needed, never resurrect a stale copy. Binary downgrade follows the canonical schema fence, not an unsafe reverse file swap.

### 6. Better for this use: capability matrix and measured Neo4j baseline

“Better” is an acceptance claim for the defined personal-knowledge workloads, not every database feature. All relevant query tasks must have equivalent released-path results; warm multi-hop latency must match or beat the measured baseline, while governance, epistemic explanation, context inclusion and embedded operations add concrete value. A slower required task or missing reachable capability keeps preview; do not rename a failure into a deliberate omission.

| Neo4j/Cypher capability family | Exomem disposition for the specified use |
| --- | --- |
| Typed directed/symmetric edges, labels/properties and indexes | Match via typed nodes/edges and declared dimensions/adjacency indexes |
| Variable-length paths, directed/type-filtered traversal | Match within explicit hop/work bounds via recursive CTEs; no unrestricted walks claimed |
| Unweighted shortest path, equal-length ties, all paths up to k | Match bounded simple-path semantics; deterministic tie path, exact/refusal on exhaustion |
| Pattern match, reused variables, optional match | Match bounded anchored patterns; optional right admission retains a released left row, as in declared left joins |
| Aggregation over paths, distinct, sorting, paging | Match exact bounded count/distinct endpoints/length reductions and typed grouping/keyset pages |
| Boolean property filters, projections, temporal buckets and null behavior | Match through unified typed IR; document legacy-v1 differences rather than claiming Cypher syntax parity |
| Subqueries, UNION, UNWIND/list comprehensions, dynamic expressions | Specified patterns/joins/aggregates match required tasks; unrestricted language constructs deliberately absent, no full-Cypher parser |
| CREATE/MERGE/SET/DELETE, transactions, schema constraints | Existing governed authoring/collection leaves provide needed writes/uniqueness; query surface is read-only. Unrestricted graph writes/deletes deliberately absent to preserve authority/history |
| Weighted shortest paths, PageRank, community detection, degree/betweenness/eigenvector centrality | Dedicated graph/GDS tools win; algorithms deliberately deferred because this workload requires epistemic paths, not structural-authority scores. If a required personal task needs one, add an admitted deterministic analytics IR/job in a later change; no delivered parity claim |
| Full-text/vector/spatial indexes, similarity/procedures/APOC/plugins | Declared FTS and existing retrieval ranking meet specified recall; spatial/unsafe procedures/plugins deliberately not needed. Global hidden-index relevance is not an admissible substitute |
| User auth/RBAC, fine-grained security editions | Beat the use-specific semantics: per-node/edge/author release, evidence obligations and every-hop withheld-as-absent proofs integrated in the same IR. Neo4j can implement an application equivalent; compare that too, not just an ungoverned toy |
| Epistemic supports/contradicts/supersedes, evidence and authored currency | Beat out-of-box behavior through native provenance/currency contract and independently judged explanation tasks; a custom Neo4j application can add these semantics |
| Context compiler, cached query/path working-set units | Beat out-of-box workflow via every-turn bounded activation and measured inclusion/source gains |
| Embedded/zero-ops per vault, portable single snapshot and row/edge transaction | Beat deployment burden for this use: no graph service/JVM/credentials, one store and portable snapshot, verified collection-link atomicity |
| Clustering, replication/HA, distributed execution, enormous fan-out and parallel analytics | Dedicated server wins; deliberately outside personal embedded tier. Future backend adapter/tier has separate replication/migration governance contract |
| Query planner/profiling, cost preview and language ergonomics | Match logical explain/index/access and bound estimates; beat user burden through agent tools/skill, no SQL/Cypher learning; verify agent task success |

This covers the relevant Cypher/operator and database capability families; version-specific additions or a missing required workload extend the preregistered matrix before a claim. It is not a false exhaustive assertion over every plugin/edition. Neo4j's optimized adjacency, graph algorithms, parallelism and mature arbitrary query planner still win on graph-wide analytics and huge hosted graphs. They do not block the specified bounded personal corpus; the benchmark, rather than that reasoning, decides whether embedded execution is sufficient.

Build a deterministic invented corpus of **100,000 nodes / 500,000 edges**, including document/unit/collection nodes, supports/contradicts/supersedes and multi-level custom subtypes, provenance, hierarchies, cycles, parallel edges, missing/withheld endpoints, moderate skew and source evidence. Record seed/degree distribution; headline 3-hop cases have p99 admitted degree ≤64, while adversarial high-degree cases prove cost refusal separately. Run 1-hop, typed variable 1..3-hop, shortest, all-path k≤3, pattern, aggregate, mixed row/page and why-connected tasks with an independent reference oracle. Add scale probes at 1 million/5 million/10 million edges, reporting all limits rather than extrapolating the small graph claim.

Pin Neo4j edition/version/image digest and driver, and pin Exomem wheel, Python/SQLite/adapter/skill. Match hardware, corpus, node/edge properties, release policy, indexes, concurrent writer load and response projection/bytes. Use unweighted simple-path semantics, identical subtype closure and tie handling, so neither baseline has less work. Measure ungoverned on both for engine comparison, then the same released corpus with application governance/epistemic implementation on Neo4j. Report governance compilation/cold admission/setup/transport separately; headline warm query times include plan/binding/admission through result serialization in both engines, excluding network transport for each. No post-filtered Neo4j count is considered an equivalent governed result.

After 20 warmups, ≥200 samples per workload cell, three runs on quiescent recorded Linux/Windows hosts; report p50/p95/p99, scanned/admitted/returned nodes/edges, plans, RSS/cache/temp, write/audit cost and deadline/refusal rate. Require **3-hop typed traversal p95 ≤50 ms at 100k/500k** and **p95 no greater than the Neo4j baseline for every required matched multi-hop/path/pattern cell**, with equal correctness and ≥99% admitted moderate-degree calls completing. Cold mixed-policy preparation is separately reported; it cannot be hidden in a warm latency assertion or claimed to fit the compiler if it does not. No baseline available means comparison pending.

Use collection design §15's real-MCP agent benchmark (≥60 held-out graph/mixed/ontology questions). Compare bare Neo4j plus agent schema/Cypher guidance and an application-governed Neo4j baseline. Require ≥95% correct graph answers, ≥90% first executable query, ≥90% repair within 2 revisions, zero hidden disclosure and ≥15 percentage-point improvement in provenance/currency/context task correctness over the bare baseline; application-equivalent tasks require at least equal correctness and no worse latency. Embedded deployment acceptance is zero separately managed database services and a verified single-store portability/transaction journey. Failure leaves capability preview and comparative wording unclaimed.

### 7. Backend-neutral scale path

Adopt collection design §15's engine-neutral admitted IR and tier triggers. The embedded target is 10^5–10^7 personal edges; the measured headline is 100k/500k, not a claim that all 10-million-edge traversals take 50 ms. At 1m/5m/10m edges record typed traversal p95 targets ≤75/100/150 ms respectively for the same ≤64-degree, admitted ≤50k-edge workload; pass the 200 ms hard deadline, memory and writer fairness gates before declaring those tiers supported. Compiler work stays ≤30 ms overall or abstains at every tier.

Beyond 10 million edges/rows or 20 GiB live store, or three benchmark runs missing single-writer/replica/latency gates, propose server migration. Postgres is a candidate for transactional joins and recursive paths; DuckDB is an analytics candidate over a governed consistent snapshot, not a transactional drop-in; a dedicated graph store is a candidate for high-degree traversal. A billion-edge tenant needs partition routing, cross-partition consistency, bounded hot sets and asynchronous global algorithms. Future targets are partition-local path p95 ≤100 ms, interactive row p95 ≤200 ms and ≤256 MiB/query; unrestricted billion-edge all-path work has no interactive promise. Implementation/provisioning of those engines is deferred.

Adapter `capabilities/plan/estimate/execute/cancel/snapshot/bind-release` must compile admitted IR with stable ontology refs and deterministic path ordering; tests run against a fake backend to prove agents and tool schemas do not encode SQLite syntax. Every real backend must pass reference and hidden/absent twins at each hop, aggregate, explain, cursor and cache before publication. Missing governance/currency operations refuse unsupported; a backend change never exports unrestricted rows or weakens policy. Tenant migration is explicit and fenced with snapshot/equivalence/rollback proof, not an automatic scale-up on a slow query.

## Risks / Trade-offs

- Moving a derived graph into canonical storage makes old whole-file replacement dangerous → projection namespace, fenced mapping cutover and source/collection head invariance tests.
- File/registry writes remain non-atomic with SQLite → durable checkpoints/replay, current-source proof and explicit warming/abstain.
- Bounded exhaustive paths grow combinatorially → simple-path state, released fan-out/work caps and refusal before claiming exactness.
- Cold mixed release and transitive ontology can miss compiler budgets → cached admitted bases, exact invalidation and bounded abstention.
- Dynamic vocabulary changes can alter meaning → stable IDs, version history, alias/replacement validation and unavailable views on incompatible merges.
- A dedicated graph DB may beat required latency → measured comparative gate; keep preview rather than assert superiority from features alone.

## Migration Plan

1. G1: after shared IR/admission and parent store interfaces are available, implement ontology identity/closure behind graph-query preview with source-vocabulary parity.
2. G2–G3: dark traversal/path/pattern compilation, independent reference and withheld/absent proofs; no public graph-ready claim.
3. G4: prove combined-store migration and replay/crash/lease/backup invariants; do not replace the combined store during rebuild.
4. G5: publish non-frozen MCP lifecycle, graph skill/bootstrap and bounded compiler path units after shared collection surfaces; frozen candidates unchanged.
5. G6: run independent integrated review/full checks, Neo4j/agent/activation/scale gates; release graph-query preview only after passing required targets, then verify portability and ordinary queries/writes.
6. After merge/release evidence proves all non-optional tasks shipped, sync/validate/archive through OpenSpec. This design lane neither checks implementation tasks nor archives either change.

Rollback disables new graph operations, preserves canonical collections and file sources, and serves legacy graph only with a current proof. Unsupported older readers refuse the migrated schema. No manual sidecar deletion or service/index operations in this design lane.

## Open questions

1. **Consolidation choice:** move the edge/vocabulary store? **Recommendation:** yes; retain replay/currentness and switch table mappings instead of whole-file replacement. No blocker found in source, but migration tests gate publication.
2. **Personal fan-out/hops:** 5 hops/64 default/256 hard fan-out? **Recommendation:** yes, explicit bounded exhaustive semantics; compiler tightens to 3/8. Benchmark before raising any cap.
3. **Shortest path weights:** include weighted algorithms now? **Recommendation:** unweighted personal relation paths only; weighted shortest/GDS algorithms are explicit non-delivered capabilities, revisited when a real personal question needs them.
4. **Ontology identities and merges:** preserve names or IDs? **Recommendation:** immutable term IDs, versioned aliases/replacements, atomic rebind and explicit unavailable on semantic incompatibility; never silent string substitution.
5. **Neo4j claim:** what qualifies as better? **Recommendation:** all required matched tasks correct and no slower, plus measured governed epistemic/context advantages and zero-ops portability; keep comparative claims pending until baseline gates pass.
6. **Hosted backend:** implement now? **Recommendation:** no; deliver admitted IR/adapter contract now, benchmark future Postgres/analytics/graph candidates under the same corpus at the tier trigger.
7. **Currency and stale projection:** should the compiler use last-known graph? **Recommendation:** no; source/registry/checkpoint mismatch abstains, and authored relation currentness cannot be replaced by file mtime or a hidden successor.
8. **Release ordering:** must collections wait for graph? **Recommendation:** no; ship verified collection phases first in the same cohesive batch where possible, and advertise graph only after G6. Cross-domain graph tasks remain unavailable until that gate.
