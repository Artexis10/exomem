# Tasks

Stage 1 starts after the passage-evidence and captured-source-inventory work (#2852) merges to `main`. That delivery adds the Stage 0 requirement, "Enrolled Sources stay off shared generated pages" (design D5). No task here changes its contract.

## 1. Stage 1: typed service API, first version

- [ ] 1.1 Declare service operations in the command registry: operation name, rendered command, fixed or narrowed arguments, request model, result model, declared codes and the identifier that makes a repeat safe. Declare the D1 set. Verify: a registry test fails for an operation whose command is missing; the conformance run (1.13) and each rendered leaf's tests fail on any code that the operation does not declare.
- [ ] 1.2 Give each rendered leaf a typed result model. Mark every field required, with `null` for an absent value. Type codes and result states as strings with `x-exomem-known-values`. The MCP door keeps its current reply. Verify: each leaf's result validates against its model in the existing leaf tests.
- [ ] 1.3 Extract one HTTP renderer from `server_rest.py`: route binding, body decoding, error envelope and OpenAPI generation. Serve the personal REST facade as its personal profile. Verify: the facade's existing tests pass unchanged, and its generated document is byte-identical before and after.
- [ ] 1.4 Add the service profile at `POST /service/<version>/<operation>` for versions that `EXOMEM_SERVICE_API` lists. Mount it behind the bearer verification that sets the request user. Extend `CloudOriginMiddleware`'s path match to the service prefix. Verify: with the setting unset, every service path answers as an unknown route and runs no leaf; under enforcement a valid bearer without a proof receives `CLOUD_PROOF_REQUIRED`, as on `/mcp`.
- [ ] 1.5 Extend `cli_ops.http_status_for` with the D4 classes: 401, 403, 404 for resource not found and operation unavailable, and 500. Add the pre-leaf codes `OPERATION_UNAVAILABLE` and `INVALID_REQUEST`. Set `Retry-After` on 503, and count undeclared codes by operation. Verify: the REST facade's existing status tests still pass; an unknown field returns 400 `INVALID_REQUEST` naming the field.
- [ ] 1.6 Write one call-ledger row for each authenticated service call, with the service transport, version and operation, and return its request id. Record a null operation for an operation that the cell does not serve. Verify: the ledger's content-free test covers a service passage search, a refused service call and an unknown operation whose path never appears in the row.
- [ ] 1.7 Give each service call the request-scoped deadline from `EXOMEM_MCP_REQUEST_BUDGET_SECONDS`. Verify: a service passage search under a tight budget names its skipped stages as the MCP call does.
- [ ] 1.8 Generate the first version's OpenAPI 3.1 document and commit it. Serve its committed bytes at `GET /.well-known/exomem-cell/service-api/<version>.json` without a credential. Verify: a test fails when the generated document differs from the committed copy; every successful response in the conformance run validates against the document.
- [ ] 1.9 Add `oasdiff breaking` with `--fail-on ERR` to the pull-request tier. It compares the committed document with the base branch's copy. Verify: a removed result field fails the check; an added error code and an added optional request field pass.
- [ ] 1.10 Add the `service_api` section to cell discovery: each served version, its document path, the SHA-256 digest of the served bytes, the operations that the cell serves and any retirement date. Verify: the advertised digest equals the digest of the served bytes; with the setting unset, discovery lists no version. When #2852 has merged, move this requirement from `service-cell-contract` into a delta on `cell-service-identity`.
- [ ] 1.11 Change the platform chart so the gateway forwards the service prefix and the document path with the same proof. The gateway release that implements the forwarding comes from the gateway's repository and is a dependency, not a task here. Verify: on a disposable cluster, a service call reaches the cell with a valid proof, and a call for another cell receives 401 before any leaf runs.
- [ ] 1.12 Allowlist `EXOMEM_SERVICE_API` in the closed pod template of `contain-cloud-controller-compromise`, if that template is in force when Stage 1 ships. Verify: the admission tests accept a cell with the setting and refuse an unlisted environment name.
- [ ] 1.13 Run the conformance check on a disposable cell: each operation through both doors with equal arguments on equal state. Remove per-call identifiers and timestamps before the comparison. Verify: the service result equals the MCP leaf result for every operation; a restricted credential receives the same authority code through both doors; a revoked login session is refused on both doors.
- [ ] 1.14 Measure passage search, capture, reservation and settlement through both doors in one run on the passage reference corpus and hardware. Verify: the service door meets the passage bars and the 1 s reservation and settlement budget, and its capture p95 does not exceed the MCP door's. Record both doors' results in the delivery evidence.
- [ ] 1.15 Write the integrator guide: the day-one steps from design B, the status table, retry safety for each operation and the versioning rule. Verify: an integrator can generate a client and capture, settle, search and inventory one Source from the guide alone on a disposable cell.
- [ ] 1.16 Record the first consumer's acceptance run with a client generated from the first version's document on a disposable cell. Verify: the consumer's capture, convergence, passage search and verification pass with its service transport setting on, and its MCP transport still passes with the setting off.
