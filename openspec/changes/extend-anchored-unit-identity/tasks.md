This change starts after the owner's vault switches to store mode and stage 2 of `make-vault-store-canonical` ships. A group waits only on what its heading names. Each group from 1 on ends with its highest-level check.

## 0. Before the build

- [ ] 0.1 Read the shape that stage 2 shipped: the anchor write for a relationship end and its write-admission rule, the anchor-to-id table and store-assigned unit id (5.5), unit-level link edges (5.2), and the review item for a removed unit (5.6). Read `add-unit-level-supersession`'s promotion (its decision 9) and `STALE_UNIT_REFERENCE` as shipped. Record any difference from design A2, A4, A5 and A7 in the design.
- [x] 0.2 On a read-only copy of a real vault, count the soft references that name a unit without an anchor, and how many a read path saved. Done 2026-11-24 with the product's own parsers. Working set, 30 days: 5,997 rows, 4 references to one unanchored unit, all position references. Page text: 5,369 memory references, none unanchored. Corrections: 7,883, none unanchored. Episodes: 3 conversation references, none unanchored. Compiled history: 372 unit references, 98 stale, saved by the writer. The owner chose anchors over full records on these counts.

## 1. Anchors for soft references

- [ ] 1.1 Add the anchor-request table, indexed by unit and by next-attempt time, and the alias table, indexed by replaced reference and by unit id, as owner objects under `vault_store_owner_schema`, named in `store_mode_objects`. Move the owner-schema version so the registry pass creates them. Add no column or index to a collection-schema table.
- [ ] 1.2 Let every save of a soft reference in store mode (the served-context record, memory references, the correction and curation writers) hand each fingerprint-bound reference and the saving principal to the store thread through a bounded in-memory queue of 256. Drop a request when the queue is full or the process has no store thread, and count the drop. The save never waits or fails for it.
- [ ] 1.3 On the store thread, record one request per unit and saving principal. Each step, take up to 32 due requests, oldest first. End a request whose unit no longer carries that reference, or whose requesters may not write the page. Back off, doubling from `edit_back.SETTLE_SECONDS` up to 300 s, while the file changed within the settle window, its hash differs from the manifest's, or the page is not projected. Otherwise commit one governed write that adds only the anchor, binding the page revision and `Expect.projected`; in the same transaction give the unit a stage-2 unit id if it has none, record the alias and end the request. Expire a working-set request after 30 days; keep a request from a memory reference or a correction until it lands or its unit changes.
- [ ] 1.4 In reference resolution, resolve a reference that has an alias through the alias alone, with one indexed lookup, and never fall back to the exact match; answer stale when the aliased unit lost its anchor or was retired. For a caller who may not see the alias's unit, answer exactly as the same reference answers without its alias. Let writes follow aliases as reads do. In the link resolver, follow the alias of a unit fragment that no longer resolves on its page, with one batched lookup per derived page.
- [ ] 1.5 Report in status the count of pending anchor requests with the oldest age, and the counts of dropped hand-offs and of ended and expired requests. Only the owner's status names their pages.
- [ ] 1.6 Highest-level check: on a real-vault copy, a recall that saves a working-set entry for an unanchored unit returns without writing; the anchor lands once the file is quiet; a later edit of the unit's text keeps the saved reference resolving. Of two identical unanchored units, the anchored one keeps the saved reference. A file changed within the settle window, or saved and not yet imported, waits; a unit changed first gets no anchor; a reader that may not write the page gets none. A scripted editor that saves while the anchor job runs opens no held item in 100 runs, or, when the projection race fires, a held item whose keep-mine drops only the anchor.

## 2. Unit operations by reference

- [ ] 2.1 Add the unit operations of design A4 as page writes that bind the revision they read, with an optional caller revision: update, insert, retire, move and embed. An operation on an unanchored unit writes its anchor in the same commit, gives it a unit id, records an alias and replies with the anchored reference. A fingerprint-bound reference that matches nothing and has no alias refuses with `STALE_UNIT_REFERENCE`. A promotion follows supersession's decision 9 and keeps the compact line's block id.
- [ ] 2.2 Route `observe_memory` add, update and remove, and the stage-2 claim operations, through the unit operations.
- [ ] 2.3 Let a move keep or rewrite the anchor, record an alias from the old reference, move stage 2's anchor-to-id row, and rewrite the unit's inbound embeds and unit-level links in its commit, only on pages within `move_file.MoverView.scope` that the mover may write, up to the move bound that 5.3 sets. Leave every other referring page on the alias, name the visible ones in the reply, and list them all in an owner review item. Refuse beyond the bound with `UNIT_MOVE_TOO_WIDE`, naming the count in scope and the way forward: embed the unit from the destination instead.
- [ ] 2.4 Refuse an operation that needs an anchor in a visible page that the caller may not write, such as an embed's home page, with `UNIT_PAGE_NOT_WRITABLE`, naming that page and changing nothing.
- [ ] 2.5 Let the duplicate fold move the copy's stored relationships to the canonical page's unit with the same anchor and record an alias for each copy reference.
- [ ] 2.6 Update the skill scaffold so agents change a unit by its reference and know `retire_units`.
- [ ] 2.7 Highest-level check: an agent updates an unanchored unit's text through `observe_memory` three times, then moves it to another page that another page links to with `[[Old#^a]]`. Its reference after the first update, its unit id and its stored relationships stay the same; the link names the new page; a reference saved before the first update resolves to it. A stale fingerprint-bound reference refuses with `STALE_UNIT_REFERENCE`. A restricted mover, connector-limited or not, leaves a hidden embedding page untouched and uncounted; that page's embed resolves through the alias and an owner review item lists it. A visible page that the mover may not write keeps its embed and the move commits. An alias to a unit that the reader may not see answers stale.

## 3. Embeds

- [ ] 3.1 Let an embed of an unanchored unit write the home page's anchor in the same commit. For a rich unit with an `id`, name the first block id in body order that is unique on the page; else write one at the end of the body's first paragraph, which the Markdown block parser finds: the unit's `id` when it is a valid block id and matches no block id or unit anchor on the page, else a generated one that matches none. Refuse a body with no paragraph with `UNIT_EMBED_NO_PARAGRAPH`, naming a unit-level link as the way forward. Let `observe_memory` treat block names as taken when it generates an anchor.
- [ ] 3.2 With the Markdown block parser, never a line regex, let the parser read the block ids of the body of a rich unit with an `id` as Obsidian names blocks: a ` ^x` that ends a block's last line, or a standalone `^x` line right after a table or code block, never inside fenced or inline code. Read them as the unit's block names rather than as text, in file mode and store mode, and record them beside the unit row in an owner index by page and name. Let the link resolver resolve `#^<name>` with one batched, indexed query per derived page, and answer ambiguous when two units share a name, an anchor included. Refuse a governed write that would create a shared block name with `DUPLICATE_SEMANTIC_ANCHOR`; open the review item when a hand edit creates one, and let the registry pass open it for each existing link that a clash makes ambiguous. Let the preflight and the review item treat a block name that an embed or link uses as they treat the anchor. Bump the lexical parser version so the registry pass derives every page again.
- [ ] 3.3 Let a page read expand embeds one level deep in one batched query, up to 64 embeds and 256 KiB, say when it stopped at the bound, and answer an embed whose home the reader may not see as a missing unit.
- [ ] 3.4 Highest-level check: page B embeds a compact and a rich unit of page A; both render in Obsidian on the real-vault copy; a hand edit of either in A shows in B without a write to B; promoting the compact unit keeps its embed rendering; the rich unit's identity, content and fingerprint are unchanged by its block id; a person's existing block id is reused; an `id` such as `claim_1`, or one that collides with another block id on the page, gets a generated block id; adding an opening paragraph keeps every embed resolving; a page with 100 embeds returns 64 and says where it stopped; a copied block name and a block name equal to an anchor both answer ambiguous; from the real-vault copy, record the count of rich units with an `id` whose body holds a block id, of the existing links into them that become unit-level edges, of block names that clash with an anchor, and of block ids that equal their unit's own `id` (expected 0).

## 4. Referenced units

- [ ] 4.1 In the semantic writer's preflight, refuse with `REFERENCED_UNIT_CHANGED` a write that removes a referenced unit or its anchor, same-page links included, unless the write names the unit in `retire_units`. Count a unit that the write moves as kept. Look up references with one batched, indexed query, read inbound unit links by stage 1's lag rule, and answer references from pages the writer may not see as absent. Add `retire_units` to the page-edit tools.
- [ ] 4.2 Extend stage 2's review item for a removed unit to embeds, unit-level links and a kept unit that lost its anchor. List and count only the referring pages that the reader may see, 50 at a time, and withhold from a reader any item whose referrers are all hidden from that reader. Name no review item in the reply of a write whose dropped unit has only hidden referrers. Add its three repair-tool choices: restore the anchor, attach, retire.
- [ ] 4.3 In the importer, look up a changed file's removed references with one batched, indexed query, and import a page that holds referenced units only after its bytes stay unchanged for `edit_back.SETTLE_SECONDS`.
- [ ] 4.4 Highest-level check: a page edit that would drop an embedded unit refuses and names both ways forward; a write that removes a same-page `supersedes` target refuses unless `retire_units` names it; a write that drops a unit that only a soft reference names commits; a write that drops a unit that only a hidden page embeds commits and opens the owner's review item; deleting an embedded unit by hand opens a review item that names the embedding page; typing after its anchor opens one that offers to restore it; attaching it to another unit of the same page makes the embed resolve again; a scripted editor that saves every 300 ms while it types opens no review item.

## 5. Compatibility, rollback and acceptance

- [ ] 5.1 In rollback to file mode, rewrite every embed and unit-level link that resolves only through an alias to the unit's current reference, as governed writes that commit before the projection drain. Refuse when a page cannot be rewritten, unless `--export-aliased` exports the list beside the vault. Then export the aliases with D8's exports, and load them in a later migration.
- [ ] 5.2 On a disposable copy of a real vault: run this change's build on a stage-2 store, then an earlier build, then this change's build again; the collection schema equals stage 2's throughout, and aliases and pending requests resume. Run a rollback to file mode and a migration back, and check that a moved unit's old reference resolves again.
- [ ] 5.3 Measure on the same instrument before and after this change: a page write's and a unit operation's hold of the vault mutation boundary, which may not grow beyond the page write's run-to-run spread; unit moves with growing counts of referring pages, from which the move bound is set so that the hold stays under the 5 s acquire timeout on that instrument; and an expanded read of 64 embeds, which adds at most 50 ms at p95.
- [ ] 5.4 Archive this change only after `make-vault-store-canonical` has archived, so its MODIFIED requirement has a base.
