## Context

Read-side activation, recurring-entity maintenance, governed vocabulary, curation receipts and host hooks already exist in separate tranches. They do not yet demonstrate that an ordinary rich episode becomes complete durable state and improves the next conversation. A post-write sweep inherits the first write's omissions; a hook that treats any successful write as completion cannot detect them. The synthetic activation corpus also needs actual product structure and publication before scorer results establish compiler behaviour.

This change is the integration owner. OpenSpec is the engineering specification; Exomem Planning records intent, status and pointers here. Checked tasks, merged code, installed versions and live enabled behaviour are separate facts. Implementation starts by checking each dependency at the current revision, including concurrently developed identity, anchor and convention corrections.

## Goals / Non-Goals

**Goals:** ordinary use reliably captures supported durable changes, enriches canonical identities and typed relationships, and supplies useful bounded context later. Achieve this across supported clients without routine user nudges, vocabulary hardcoding or release publication on every development iteration. Include adaptation, hot profile, activation priors and consolidation in the delivery programme.

**Non-goals:** a replacement storage engine, a second mutation executor, a server semantic author, mandatory full-transcript retention, automatic user commitments, relationship quotas, a fixed domain ontology or guaranteed lifecycle interception in hosts that provide none. This plan neither activates authority nor enables live background work.

## Decisions

### 1. One loop, separate decision and execution responsibilities

`turn -> activate -> active agent reasons -> decompose episode -> resolve homes and identities -> permitted canonical writes -> publish projections -> future activation`

The active agent decides meaning, importance, equivalence, candidate disposition and whether a specific relationship is truthful. Deterministic server code supplies bounded evidence, validates structure/identity/authority, runs existing writers and reconciles receipts. Episode compilation extends existing review/curation coordination, not a generic executable-plan payload or autonomous server LLM. Capture sweep remains useful after writes but is not the decomposition trigger or completion authority.

### 2. Decompose before selecting destinations

At a substantive episode boundary, the agent enumerates supported durable changes from the original input: observations, outcomes, entity candidates/facets, relations, Records events, expressed Planning changes, provenance and structural routing. It resolves each against current knowledge before writing. One episode may produce several destinations or none; every candidate receives a disposition with a reason. Importance may justify first-mention promotion; recurrence is supporting pressure, never a name-count quota. Incidental names and uncertain identity remain unresolved.

Preserve epistemic distinctions: direct user verification, hearsay, agent inference and comparison are different claims. An exposure during an experiment is an event, not evidence of causal effect. Planning writes require expressed intent; a mentioned possibility is not an automatic commitment. Completeness is an agent attestation against an input revision, not a server proof of semantic exhaustiveness.

#### Destination fitness before commit

Retrieval similarity identifies material to inspect; it does not establish canonical ownership. A named synthesis can be strongly related to several existing pages while belonging under none of their narrower titles. The active agent compares title and declared scope, semantic/artifact role, independent meaning, expected future lookup language, consequential facets, supported relation fan-out, synthesis versus refinement and continuation value. These are considerations, not server scores, fixed weights or minimum facet/edge counts. A stable name alone does not justify a new page. The benefit of a focused home must outweigh fragmentation and duplication.

Extend the same episode candidate plan with bounded destination decisions: update an existing page, add a semantic unit there, create a focused note, create/hydrate an entity, route to an existing Records/Planning/experiment role, preserve Source/Evidence, add a relation only, or make no durable capture. Role-specific writers and authority remain unchanged. A multi-part candidate may map to several leaf effects; related context pages do not receive copied observations unless their own scopes own the information.

For substantive routing decisions, retain the candidate/input revision, selected route, proposed title or current target identity, bounded inspected alternatives with their current scope/version evidence, and a concise active-agent reason. Record a focused home separately from supporting context. Missing or truncated search evidence must remain explicit; it is not proof of absence. Validate the record through the episode prepare/disposition operations, bind it to the existing leaf preparation, and use current target guards at commit. A destination change revises the proposal without changing an already attempted equivalent candidate/leaf identity. The server validates evidence references, bounds, coverage and stale targets; it does not infer title fitness or silently promote a concept.

Before the first commit, the active agent checks the destination plan against the original episode revision: all identified candidates have a route or an honest abstention/defer/authority disposition, and no independently useful synthesis is buried merely because a related page ranked highly. After execution, reconcile actual receipts/readback and repeat coverage against the same input revision. The precommit review is not a new confirmation prompt and grants no permission. The postcommit sweep and lexical/vector structural audits remain safety nets; a successful write or a generic overload warning is not proof of correct routing.

The first acceptance pair uses a synthetic product discussion whose broader, explicitly named operating thesis synthesizes five existing narrower notes, and a matched minor refinement that should remain a semantic unit on its current page. Freeze original actor input and pre-capture vault state separately from evaluator expectations. The actor sees an ordinary discussion without save, page-creation, routing or corrective nudges. Measure retrieval of relevant antecedents, first-pass focused destination, truthful typed links, scope-owned updates and fresh-session activation. Run real public writers and publication; scripted correct writes establish plumbing only, never ordinary-agent success. Keep exact private conversation replay local and label reconstruction or unavailable original input honestly; corrected pages cannot substitute for the original turn.

### 3. Recoverable episode identity and evidence

Use the existing curation/review persistence boundary for a versioned episode ledger. The ledger records logical episode identity, input revisions, minimal authorized source/excerpt references, candidate identities, proposal revisions, leaf operation identities, dispositions and receipts. Preserve enough original evidence to resume without reconstructing facts from summaries; a hash alone cannot recover vanished conversation. Follow disclosure/retention policy and do not persist complete transcripts by default. If the host cannot retain required evidence, expose unavailable recovery rather than inventing it.

Candidate identity remains stable across re-planning. Proposal revisions may change targets, ordering or remaining actions, but cannot silently assign a new operation identity to an already attempted equivalent leaf. Before retry, reconcile a committed, proven-uncommitted or uncertain outcome. A changed semantic effect is an explicitly revised candidate requiring fresh validation and authority. Existing curation operation IDs currently derive from plan identity and position; integration must add stable candidate-to-leaf mapping rather than assuming a rewritten plan is idempotent.

Completion records `attempted`, `pending` and `covered_through_input_revision` separately. A final pass compares dispositions to the original episode revision, including corrections, and reads committed results. A successful tool write or a "Saved" marker cannot skip that pass. Bounded pending continuations resume at the next eligible host boundary; resource limits defer work visibly instead of dropping it. Hosts cannot recover an episode they never received or persisted, and crash coverage must state that boundary.

The first implementation slice is a pure `episode_model` beside curation, with no persistence, tool exposure or writer calls. Stable candidate and leaf keys derive identities from their episode/candidate lineage, not proposal bytes or list positions. Normalize collections by identity; preserve explicit input, proposal and effect revisions. Bounded recoverable references or authorized excerpts support an input revision; a digest alone leaves recovery unavailable. Destination records retain the active agent's route, target/title, alternatives, evidence completeness and reason.

Before an attempt, bind each supported leaf to the exact sealed curation plan, fingerprint, ordinal, step and existing operation ID. Verify normalized step semantics against its effect digest. Mark the leaf uncertain before execution; only the later trusted persistence adapter may reconcile that outcome from existing receipts, witnesses and readback. An uncertain attempt cannot be retried, rebound, removed or revised. Proven non-commit permits the same-operation retry; committed work permanently retains its original binding and proof. Exact duplicate effects cannot escape reconciliation through a new candidate/leaf key. Different intended effects require explicit revisions or new leaves while preserving attempted history.

Precommit review binds the exact input and candidate/proposal/disposition snapshot; changing that snapshot invalidates readiness. Postcommit review is a separate active-agent attestation with reconciled outcomes. Reviewed-through revision and pending work remain separate: deferred or uncertain candidates may be considered without being complete. Input corrections retain historical reviews but invalidate current readiness/coverage. The pure model validates structure and identity consistency, never authenticity of a caller-supplied receipt or semantic completeness; success observations are internal adapter inputs, not public proposal fields. Persistence must authenticate them before any public command can use them.

Existing curation currently supports note/entity/relation/edit lifecycle leaves, not Source, Evidence, Records or Planning execution. The pure slice may represent those destinations but leaves them pending until their existing writer adapters are integrated. It adds no generic execution payload and makes no automatic-capture claim on its own.

The first recovery integration is a read-only internal receipt adapter. It takes an uncertain leaf from owner-held episode state, reloads the exact sealed curation plan and approval, validates its run/plan/fingerprint/ordinal/step/operation/effect binding, reconstructs authoritative receipts, and verifies the atomic witness against current postimages before creating a committed observation for the pure model. Hold the existing vault consistency guard throughout this read so canonical writers cannot produce a mixed-time multi-path observation; this reuses the mutation boundary without requiring writer authority. It accepts no caller-supplied success proof, executes no writer and repairs no receipt. A witness without its terminal receipt remains uncertain until the existing curation owner recovers it. A historically committed result whose live postimage changed also remains uncertain under the current model rather than acquiring a fabricated current readback digest; this blocks retry while preserving the canonical evidence for later historical/current-state reconciliation. A failed receipt or absent witness alone cannot prove noncommit for the current episode attempt, because its binding does not yet identify the corresponding curation attempt. Durable episode storage, attempt-specific noncommit proof, disclosure/retention and public commands remain separate unfinished integration work.

### 4. Canonical knowledge remains readable and rebuildable

Keep Markdown semantic units and supported structured collections canonical. Entity pages hold stable identity and facets; mutable events/state belong to Records or domain stores; Sources/Evidence preserve original provenance. Hubs expose navigation and projections. Graph, search, hot profile and priors are derived and rebuildable, with explicit publication currency.

Resolve aliases and existing identities before creating another page; hydrate existing entities when supported facts accumulate elsewhere. Use registered relations where accurate and propose governed extensions for reusable missing meanings. Dynamic types, including newly registered kinds, must create, inspect, retrieve and traverse through normal MCP/CLI/REST operations. No product-specific branches or fallback to generic file writing as the normal dynamic-type route.

For a missing reusable relationship meaning, the active agent first inspects the current registry and bounded candidates, then supplies precise semantics, a supported core parent/family and directionality/symmetry through the existing governed vocabulary owner. Validate and publish the definition before ordinary use; a saved proposal is not an active relation. Preserve edge provenance and report pending publication honestly. Honest generic relations or no edge remain valid when evidence cannot support a more specific predicate. Graph density never justifies a new type.

Vocabulary identity must be resolved before projecting a destination. Reuse the existing family registries, normalization and reviewed aliases through explicit family adapters; do not create a competing ontology or flatten domains, categories, entity instances and types into one namespace. Unique exact equivalents resolve deterministically. Multiple existing equivalents require explicit ambiguity rather than choosing a filesystem entry by enumeration order. Physical path canonicalization remains a separate safety contract.

For a non-exact proposal, provide bounded nearby definitions and representative authorized usage before the active agent chooses reuse, enrichment, a distinct new identity or deferral. Similarity never merges identities or creates aliases. Preserve the existing open-category escape hatch and each family's authority. Resolution must reach normal writers and their receipts, with requested token, canonical identity and destination, and be revalidated inside the existing serialized commit boundary so another client cannot create a case/normalization fork. Existing duplicate trees require governed reconciliation; this work does not silently move provenance.

The first implementation packet covers experiment Notes using the existing subject-domain taxonomy. It must establish the complete resolution/preparation/commit/receipt seam before Sources adopt it. Category, entity, type and relation adapters follow under their existing owners. Evidence scope is explicitly excluded from domain interpretation: incident/case/project/domain scope tokens retain their existing segment semantics until a separately defined family adapter exists. No domain aliases or slug collapsing may rewrite incident identifiers.

For writes, the taxonomy snapshot must reject malformed/unreadable registry state, duplicate normalized canonical or alias owners, and equivalent path-label collisions. The existing permissive read/bootstrap fallback is not write authority. A prepared domain binding carries the requested token, family and canonical key, canonical persisted metadata, unique existing projection spelling, registry fingerprint and bounded parent-directory census. Normalize metadata, logs and activity to the same canonical key; preserve requested spelling in the receipt. A unique legacy folder can remain the projection without becoming a second semantic identity; multiple equivalent legacy folders require explicit reconciliation.

Non-exact domains with nearby meanings return a typed non-mutating preparation before minting a committable destination. Reuse the existing validation/draft workflow, with an explicit bounded `vocabulary_decision` input carrying the evidence fingerprint, finite outcome (`reuse`, `create`, `defer`) and selected canonical key where applicable. The active agent supplies this decision without a user confirmation. `create` keeps genuinely distinct neighbours possible; `defer` commits nothing. Enriching a definition remains its existing governed registry operation. Bind the decision and canonical result into the immutable draft/token/hash; stale evidence requires fresh preparation, never a changed destination hidden behind the old token. Missing/incomplete neighbour evidence must be reported as such, never as proof no neighbour exists. Candidate definitions and representative usage must be bounded and authorized, without a foreground whole-vault scan or a model call.

Carry the registry `PathGuard` and projection-root `DirectoryCensusGuard` through `CreationPreflight`. Recheck inside the existing mutation guard and pass the guards through both structural and relation-reviewed creation branches to the atomic batch. A changed snapshot can proceed only after proving the identical prepared binding; otherwise refuse as stale. `note.py`, `semantic_writes.py` and `relation_review.py` share this proof, including composed/prepared writes, without adding a new lock or executor. Sources must subsequently adapt `add.py` and artifact-adoption validation to the same domain result and avoid unguarded pre-commit destination creation.

The first slice exposes a bounded `vocabulary_resolution` record with `family`, `requested`, `canonical`, `destination`, `match_kind` and `snapshot` in validation, committed and replayed results, including compact and full terminals. The family is `domain` across projection adapters; Notes does not create a separate identity namespace. Extend the existing receipt validators/projections explicitly; do not rely on an internal result field surviving the public surface. Canonical MCP/CLI/REST definitions and generated contracts carry the same finite decision input. Public fixtures cover malformed registries, alias ambiguity, canonical metadata, pre-destination neighbour choice and stale registry/directory changes as well as the reported case forks.

Version any changed draft encoding. Legacy experiment drafts without a canonical binding require fresh validation; other note types retain their existing token semantics. Replaying an already committed receipt remains a readback of that original effect and never repeats or relocates it. The binding is validation evidence, not a permission grant.

Every fan-out destination retains its originating episode/source/span identity. Compilation cannot increase the number of independently established input origins: conversation-only fan-out inherits one episode origin, while independently established original sources discussed together retain their distinct identities. Copying either source into more pages adds no independent evidence. The write-time carrier and background detector must agree; where independence cannot be established, report it as unassessed rather than count pages as independent mentions.

#### Identity, roles and supplier provenance

Represent independently meaningful referents separately: an operator organization and its physical farm/site have different identities when evidence establishes both. Whether one can change while the other remains is a useful separation test, not sufficient evidence to create a node. Reuse existing entities first, hydrate their supported facets, and promote only referents with durable use. A trading name alone does not require a brand entity. Create an independently addressable brand only when the evidence and retrieval need justify it.

One identity may have several roles, such as operator, producer and supplier. Keep roles as governed multi-valued facets or evidenced relationships; do not create a duplicate entity for each role or use multiple type labels to conceal conflated referents. Start with the existing singular canonical type and registry parent-family contract. Prefer a reusable physical-site type with governed subtypes or facets where appropriate; choose its canonical vocabulary against current registry evidence. Farm-specific types and predicates are acceptance examples, not hardcoded defaults. Paths remain projections of identity/type metadata. Mutable role assignments, operator transitions, purchases and lot provenance retain their history in Records or canonical domain stores, with qualified current facets on the entity projection.

An entity name or alias may legitimately identify multiple referents. Preserve bounded candidate ambiguity, including omitted counts, and let the active agent use authorized episode context and candidate evidence to select a stable identity or abstain. Company-ordering context can support an organization; land/site context can support a physical location. Neither cue is a server selection rule. A shared name must not globally transfer an alias to one node, silently merge the nodes or block an explicitly justified distinct identity merely because its name overlaps. Reuse current exact/alias resolution and its ambiguity handling; extend only the missing writer/disambiguation seams under existing authority. Alias edits and identity splits remain governed restructuring.

Resolve each relationship's endpoints and predicate independently, then bind provenance and epistemic status to the authored edge. Reuse truthful registered relations or propose a governed extension with a meaningful parent; unsupported precision remains unresolved. A seller sourcing from two producers does not establish which one produced a particular purchased lot. Preserve reported versus directly verified provenance, unknown origin and later corrections at the lot/event level. Traversal may follow a supported chain but must not present an inferred shortcut as a directly sourced edge. A later operator change preserves the site identity and historical relationship evidence while current-state activation reflects only the supported effective state.

The delivery audit must distinguish registry/writer support, generated schemas, installed connector capabilities and successful public-path execution. An obsolete closed enumeration in one connector is not proof that the core writer lacks dynamic types. Reuse current lifecycle, relation-vocabulary and identity-capture work; acceptance requires registration, creation, hydration, edge provenance, publication and later bounded activation through normal MCP/CLI/REST paths. Public operator/site, multi-role, shared-name and mixed-producer fixtures are synthetic. Private sourcing episodes supply a separate local no-nudge replay, not repository fixture contents or authorization for bulk creation.

### 5. Reuse versioned authority and typed tools

`activate-agent-led-vocabulary-evolution` owns approval and enforcement. Extend its explicit opt-in contract with a vault-scoped `edge.add` grant that can cover existing and subsequently committed canonical endpoints in the same logical vault. Keep project-edge grants narrow; do not widen existing grants during upgrade. Entity/type/edge actions remain separately named. New targets must resolve to authenticated vault identity, never caller labels. The episode coordinator cannot mint a grant or bypass leaf validation.

Existing-fact replacement, alias edits, merges, deletion, meaning changes and Planning commitments do not inherit additive grants. Ordinary note/facet updates continue under their own current write policies. New role/convention editing must identify and validate its own existing authority; this programme adds no wildcard future action. Quiet operation concerns notification, not permission.

### 6. A shared core with truthful host guarantees

Canonical commands and generated schemas own the same episode and activation semantics on MCP, CLI and REST. Adapters discover actual capabilities and versions. Verify Claude Code, Codex, ChatGPT, Claude app and a generic MCP client; record installed adapter/version and what was exercised instead of assuming a brand implies hooks.

Where a host exposes pre-turn/post-turn hooks or equivalent middleware, enforce a bounded activation/decomposition checkpoint and pending continuation. Where only MCP tools and instructions are available, offer the same complete workflow through bootstrap/skill guidance and report initiation as best effort. A capable tool schema alone proves neither ordinary-agent use nor interception of tool-free turns. Keep a capability matrix separating tool parity, lifecycle enforcement, recovery and observed no-nudge behaviour.

Cross-client acceptance includes the existing `memory-reference-presentation` contract: cite human-readable titles, use a current path only for disambiguation or missing titles, and retain stable references internally. Custom-scheme links that expose opaque identifiers in a client must use plain title-first citations. This verifies the shipped contract rather than creating a new identity scheme.

### 7. Activation quality is downstream usefulness

Task-conditioned roles, anchor resolution, bounded typed expansion and current-state qualification produce provenance-bearing packets. Partial or ambiguous anchor resolution cannot masquerade as a complete current context. Evaluate rare anchors, unfamiliar vocabulary, multilingual names, cross-kind relationships, supersession, Records state, distractor padding, negative twins and unavailable publication. Keep existing budgets and false-positive thresholds; embeddings-on smoke is required in addition to deterministic lexical fixtures.

The primary integration observation is an ordinary later response using the right durable facts without a reminder. Forced tool calls test transport/compiler correctness separately. Public fixtures use synthetic identities; private episodes remain local, provenance-preserving and digest-pinned. Repair the existing benchmark instead of creating a second scorer. Paid comparative arms remain an optional, separately authorized experiment and do not block delivery.

### 8. Adaptation, hot profile, priors and dreamer are committed milestones

User corrections and observed misses create bounded review candidates tied to evidence. The active agent can propose revisions to registered context roles, cues, aliases or vault conventions; application follows each family's applicable authority, with versions and reversible history. The current `context-roles` owner-authored override gate remains in force: agent proposals do not independently grant role-edit authority. A fresh session must consume the accepted result. Do not encode one user's equipment, suppliers or language into product source. Hard identity, provenance, authority and abstention invariants remain stable.

The hot profile is a compact, derived, provenance-bearing projection with invalidation for correction, expiry, deletion and access changes. Priors affect bounded candidate ordering only; they cannot invent facts, resolve ambiguity, resurrect superseded state or override explicit task anchors. Test stale-profile and popularity-trap negatives alongside latency and usefulness.

The dreamer is bounded deterministic consolidation over changed material and indexed evidence, scheduled off the interactive path. It proposes alias/anchor, category/convention, link, hydration and profile work for the active agent. It never writes canonical knowledge autonomously. Default-off background execution, pause/quiet controls, time/memory/work budgets, checkpointed continuation, deduplication and source-version invalidation are required. Quiet optional advice cannot hide integrity failures. Online recall and capture remain usable with the dreamer disabled or failed.

Eligible proposals enter the existing bounded review/activation carrier at an ordinary supported lifecycle boundary, with evidence and current disposition, so an agent can consider them without a user review reminder. Respect quiet/defer settings and existing delivery budgets; tool-only clients retain best-effort initiation. Creating an ignored queue is not dreamer acceptance: verify next-session delivery and authorized disposition.

Frozen verifiers reuse the stricter canonical `frozen-verifiers` admission and effects contract: optional, default-off, version-pinned review labels with abstention. They cannot author canon, select entities, rank retrieval, gate capture or define policy. A verifier-admission evaluation is a programme task; enabling a model is not an acceptance prerequisite. Failure or resource pressure removes the label without changing online semantics. CPU-first evaluation precedes any separately evidenced GPU/co-tenant admission.

### 9. Three iteration loops

Development uses isolated state and affected tests. Personal candidate testing uses an immutable local wheel with recorded digest/source commit, a dedicated interpreter and the existing managed standby/admission/cutover mechanism. Public releases retain full completion checks and are batched when a tranche is ready. Neither new code iteration nor candidate source admission needs a PyPI publication; a candidate is not a released version.

The existing manager already admits interpreter/protocol/state descriptors; the staging installer currently selects only a published version and needs an explicit local-wheel source. Preserve service-manager ownership and single-writer state. Compatible descriptors can reuse completed migrations. Descriptor-changing experiments use disposable state or explicit forward-migration/recovery evidence. Never promise arbitrary rollback after a state migration. Required full-suite and release checks are completion gates, not every-edit development gates; do not rerun known failing full jobs simply to wait for a release.

First repair the test truth and add the candidate install path as independent bounded lanes. Then prove one vertical slice: an ordinary rich turn hydrates an existing supplier, resolves/creates equipment through a registered type, records supported state/provenance and a truthful relation, abstains on an ambiguous owner, publishes projections, and supplies the useful facts in a fresh session. Interrupt after one committed leaf and resume without duplicates. Extend that slice to the complete no-nudge cohort, dynamic vocabulary, client coverage and authority integration. Deliver hot profile, priors, adaptation and dreamer as subsequent required tranches; a successful first slice is not programme completion.

Each implementation packet gets current-state verification, a narrow owner, independent review proportional to its boundary, affected tests while iterating and full required checks at the finished tranche. This session remains the programme orchestrator; delegation supplies bounded implementation or independent review, not a parallel architecture authority.

## Risks / Trade-offs

- Decomposition can overcapture: require supported evidence, explicit uncertainty, incidental-name negatives and no quota for entities/edges.
- Multi-write episodes can partially commit: reuse receipts and stable identities; report pending and publication state honestly.
- Adaptation can accumulate stale guidance: tie every derived item to source versions and demonstrate correction/invalidation in fresh sessions.
- Host reach differs: publish observed guarantees, keep full tool parity, and never call best effort lifecycle enforcement.
- Broader grants increase scope: deliberate opt-in, authenticated same-vault endpoints, independent security review and no silent grant migration.
- Local candidates can migrate shared state: preserve managed admission and use disposable state unless recovery is evidenced.

## Migration Plan

Ship additive contracts and adapter discovery first with no live authority activation. Introduce episode state through versioned existing persistence; missing legacy episode metadata is unknown coverage, never assumed complete. Thread origin identity through new writes; do not infer historical independence from page count. Publish derived schema/index migrations under existing compatibility fences. Roll out no-nudge workflow per adapter with evidence, then enable optional background consolidation only under its own configuration. Preserve the old read/write paths throughout partial rollout and report unavailable features explicitly.

Archive this umbrella only when every required tranche is implemented, verified, merged and reconciled with canonical specs. Optional paid comparisons and optional verifier enablement remain explicitly deferred without falsely claiming they ran.
