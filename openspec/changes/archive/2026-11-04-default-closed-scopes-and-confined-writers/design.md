## Context

Governance decides each page from the scopes that select it. A page that no scope selects gets the open ceiling. The connector boundary (`governance/connector_boundary.py`) adds a host-owned floor per client binding. Today it lets a limited writer create only under the global `capture_paths`, and edit any existing page it may read if the result avoids its denied scopes. Without a connector config, nothing confines a non-owner writer.

## Goals / Non-Goals

**Goals:**
- Let the operator close unclassified material to every non-owner audience and fenced connector, with no reliance on agents citing sources.
- Confine every restricted writer, on every write door, to scopes the host config grants it, plus a private inbox.
- Keep membership unchanged without a residual scope, and keep writes unchanged with an empty policy and no connector configuration.

**Non-Goals:**
- Restriction that follows citations or links. An earlier draft walked declared derivation edges at read time. It protected only cited pages, opened a name oracle through the walk, and failed open on rename.
- Write permissions in policy documents. Vault content must not confer write authority.
- Exomem Cloud wiring. Cloud cells do not configure a connector boundary yet.

## Decisions

**D1. Residual scope, not a decision mode.** A scope document with `residual: true` and no selector or exclude fields is assigned when nothing else selects an item. It is an ordinary scope id, so rules, grants, release grants, connector denied sets, explain and private vocabulary instances work unchanged. A mode applied in the lattice to empty scope sets was rejected: denied sets and grants name scope ids, so it would need a parallel connector flag, a new explain shape and a new way to share, and an empty scope set would mean two things.

**D2. Exemptions.** The residual scope never selects a directory, so folders still collapse by their contents. Public vocabulary storage (overlays and registry history) counts as classified with no scope, as a v2 binding already answers; `instances.public_storage` gives the same answer for unarmed and v1 vaults. Nothing else is exempt: the skill and conventions are read without admission, `_Governance` is excluded structurally, and capture inboxes are classified by scopes.

**D3. Reach.** Non-owner audiences meet the residual scope through `default_deny`; the owner stays exempt. Fenced connectors meet it through their denied sets. The host refuses a connector config whose default denied set omits a declared residual scope. It also refuses a config that grants writable scopes when the policy declares no residual scope, because confined writers need a default-closed vault. The personal connector opts in by omitting it from its client entry.

**D4. Write authority comes only from the host config.** A restricted writer is a non-owner under a non-empty policy, including an unresolved principal, or the owner through a connector with a non-empty denied set. Administrative ingress and every caller on a vault with an empty policy and no connector config are not restricted. An unfenced owner client is not restricted. A non-owner with no writable client entry is read-only under any non-empty policy, even without a residual scope or connector config. Writable scopes come only from the matched client entry's `writable_scope_ids`; a caller with no entry has none. The host refuses writable scopes that are not policy scopes, meet the client's own denied set, sit on a client with an empty denied set, or are readable by the default context or another fenced client. The default context is therefore read-only. A rule or grant `write` field was rejected because vault content would confer authority.

**D5. Inboxes keep the global `capture_paths`.** A writer may create in a capture path when that path's membership is non-empty, lies within its writable scopes and is readable by it in full. Exclusivity (D4) makes each inbox private. For every writer, the owner included, a capture page's membership must equal its path's membership; this replaces "visible under the default denied set" in `require_write` and `verify_capture_namespaces`. Per-client `capture_paths` were rejected: an inbox scope must exist anyway, and the requirement format would need a version bump.

**D6. One gate.** `connector_boundary.write_ceiling(root, who)` feeds `require_create`, `require_write` and `decide_scopes` for mutations. Structured Records and Planning mutations apply this ceiling to their current and proposed canonical subjects, without reading projected files. Outside an inbox, a write is admitted only for an existing page that the writer reads in full and whose scope set stays non-empty and within its writable scopes, before and after the write. A move destination and a reclassified path are judged as creations. A file path refused by confinement receives `WRITE_REFUSED: target is unavailable` before any stat or name allocation. Identifier resolution and structured operations keep their existing opaque unavailable errors; withheld and absent targets answer alike. `_Schema/**` needs no special case: its pages are unscoped or residual, which are never writable.

**D7. Source, recap and note destination.** For a restricted writer, Source capture, recap and note doors redirect their generated destinations: `add.admit_source_destination`, the recap folder and the note door's folder resolution take the shared destination `Knowledge Base/<tree>/<rest>` to `<capture path>/<rest>`. The capture path is the first one, in sorted order, that lies under `Knowledge Base/<tree>/` and where the writer may create; with none, the write is refused. The tree stays, so inbox Sources stay citable and append-only, and a client that captures Sources and creates notes holds one capture path per tree. An explicit destination is never redirected. Entity creation also generates its destination, from the entity type's folder, but does not redirect it; a destination outside the writer's inbox is refused. One recap-folder helper replaces the hard-coded episodes folder in its consumers, so recaps in an inbox are listed and superseded only there. Recaps the owner records stay in the shared episodes folder and take the residual scope.

**D8. No projector change.** v4 publication and read time call the same membership functions, so they receive the completed membership. A policy with a residual scope has a fingerprint that no earlier binary compiles, so no stale namespace exists.

**D9. Caches stay page-local.** Completion depends only on the selected scopes, the registry binding, the policy fingerprint and whether the path is a directory. Page-local admission verdicts stay valid, and the write gate adds no cache.

**D10. Side effects outside the ceiling are skipped.** A door's own effects on other pages (activity log and index entries, a cited Source's `ingested_into` back-reference, link rewrites in linking pages) are written for a restricted writer only inside its write ceiling, and skipped elsewhere. Riding them along was rejected: it writes outside the confinement, puts an inbox title into a page with wider readership, and makes a shared Source change when a fenced client cites it. Refusing them was rejected: a fenced client could not cite a Source it may read, which is the purpose of a combined vault. Read egress already strips provenance entries per reader, so a skip loses only owner bookkeeping: a fenced citation does not count toward the owner's compile coverage, and the owner's audit reports a link left dangling. A Records transition is the exception: its contract requires its audit entry, so the entry is planned whatever the caller's ceiling and a caller whose ceiling excludes the log is refused by the write gate, never left unaudited.

**D11. Workflow state under the governance tree is written.** Curation runs and episode journals live under `_Governance/curation/`, and relation review records live under `_Schema/relation-reviews/`. Unlike the governance tree, the review folder is served through ordinary membership, so with no residual scope it would be open and a fenced client's records, which name its inbox pages, would land in an open place. Writable scopes therefore require a declared residual scope. A door writes them for a restricted writer, because no audience is served the governance tree (`policy.is_governance_path`) and the run store is create-only. Curation runs use content-addressed run ids; only episode journals are keyed to their audience. Without them a fenced client's episode `prepare` and `resume` fail, `record` leaves a recap without its journal, and every `remember` fails because its creation commit writes a review record. A restricted writer's write of such a path skips the membership check, because a JSON record evaluated by path alone against a semantic scope is undecided. Policy documents and the activation manifest stay refused.

**D12. A vocabulary grant is write authority for its registry change.** The vocabulary authority already needs an owner decision for each change. For a vocabulary mutation it decides before the write gate: an ungranted change receives its refusal with a request id, and a granted change is admitted to the registry storage it names. No other write gains authority from it. Making non-owner sessions unable to change vocabulary under a governed policy was rejected, because it would silently remove a shipped owner-approved workflow.

**D13. Durable imports retain identity, not write grants.** An import job retains its verified client and origin-session bindings without a bearer. Each authority check revalidates the origin through the existing session authority and reads the current host configuration. A revoked origin pauses the job at its committed checkpoint; a failed commit check rolls the batch back. Missing binding fields in older jobs confer no client authority. Audience and issuer still define job ownership; explicit continuation proves the current caller's authority. The synchronous writer uses a context-preserving bridge to the existing asynchronous origin validator. This prevents a revoked login from retaining host write authority; an unavailable validator costs import availability, with progress preserved for explicit continuation. A Cloud job without current gateway proof cannot manufacture that proof from its stored identity.

## Risks / Trade-offs

- [Fenced connectors lose write-down into open pages and unscoped inbox creation on upgrade] → Deliberate; the scaffold skill documents inbox scopes and `writable_scope_ids`.
- [Owner capture writes in an armed vault become stricter: metadata that changes a capture page's scopes is refused] → Deliberate; the invariant keeps every inbox private.
- [A scope document edited outside Exomem, for example by sync, can declassify residual pages while serving] → The requirement pins only protected documents; pinning every scope would force stopped maintenance for every classification. Reported as a known limit.
- [Two connectors that share one episode key could shadow each other in recent context] → Recaps are grouped per audience token; reported as a known limit.
- [An older binary refuses `residual`] → It blocks the policy, which fails closed.
