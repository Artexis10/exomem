## 1. Refusal of declared Records values before queueing

- [x] 1.1 Add `record_memory.value_refusal`, which reads a collection's declared fields as a request thread reads them, within a fixed time, without a lock and without recording a release.
- [x] 1.2 Apply it in `commands.declared_refusal_before_queueing`, only for a save about to queue, and pass its refusal through the terminal egress filter. Keep raising an argument refusal when that filter faults.
- [x] 1.3 Keep the save queued while a queued save may change the declared fields: a command that declares `sets_any_frontmatter_field`, or a Records or Planning save that carries a manifest's text. Record this once on each save at its acceptance. Count a save without a record, which an earlier release or a store from before the record wrote. Give such a store the empty column and its index at its next acceptance, reading no stored save. Mark the queue before the declaration read and after a refusal look again from the mark, each by index seeks whatever the queue holds, so a save open at the mark or queued after it counts even once it has committed.
- [x] 1.4 Tests: an undeclared value behind the queue is refused and never queued, for a row whose real key and guards the commit accepts; a declared value still queues; behind a queued revision, an update of the row by its id queues and its replay saves the value; behind a queued edit of the manifest named by title or reference, the value queues; an argument refusal still comes back when the egress filter faults.
- [x] 1.5 Add `plan_memory.value_refusal`, which runs the Planning commit's rule for each governed field and the per-field rules of the declared fields, through the same declaration read as Records. Refuse an add's explicit null as the commit does. Refuse an update or triage only where the owning store reads the item it names by `plan_id` and both guards, by its key at that version, and the item does not store the value, as the commit's rule does; a file collection or an `item_id` queues.
- [x] 1.6 Tests: an add's Planning status outside the Planning values or null, and a custom field's undeclared value, behind the queue are refused and never queued, as the direct call refuses them; a declared value still queues; behind a queued Planning revision, and behind one that commits while the intake reads the old manifest, a value it declares queues and is saved; a file collection's update or triage with an undeclared status queues and its replay refuses it; a busy area add with a status and an undeclared custom value queues and its replay refuses it for what an area carries; a busy area update that deletes a parent it lacks is refused for its undeclared custom value; on a busy store, an undeclared status is refused, an update that keeps its own removed status queues, an update of another item to that status is refused and an update by a stale `item_id` queues.
- [x] 1.7 Bound every queue read and the declaration read by one shared budget, opening the queue and waiting for its locks included, give each statement only the time left, and treat an answer after it as unknown. Tests: a valid and a refused busy save each read no more of a longer queue; a revision open at the mark that applies during the read keeps the add queued; an ordinary save that applies during the read leaves the refusal; a store from before the record keeps a save behind its open revision queued, upgraded before the check or during its read, and its upgrade holds no stored save in memory; a revision that an earlier release queues keeps the add queued; a queue that answers after the budget, or a locked queue whose open spends most of it, queues the save within the budget.
