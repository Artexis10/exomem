## 1. Refusal of declared Records values before queueing

- [x] 1.1 Add `record_memory.value_refusal`, which reads a collection's declared fields as a request thread reads them, within a fixed time, without a lock and without recording a release.
- [x] 1.2 Apply it in `commands.declared_refusal_before_queueing`, only for a save about to queue, and pass its refusal through the terminal egress filter. Keep raising an argument refusal when that filter faults.
- [x] 1.3 Keep the save queued while a queued save may change the declared fields: a command that declares `sets_any_frontmatter_field`, or a Records or Planning save that carries a manifest's text. Record this once on each save at its acceptance. Count a save without a record, which an earlier release or a store from before the record wrote. Give such a store the empty column and its index at its next acceptance, reading no stored save. Mark the queue before the declaration read and after a refusal look again from the mark, each by index seeks whatever the queue holds, so a save open at the mark or queued after it counts even once it has committed.
- [x] 1.4 Tests: an undeclared value behind the queue is refused and never queued, for a row whose real key and guards the commit accepts; a declared value still queues; behind a queued revision, an update of the row by its id queues and its replay saves the value; behind a queued edit of the manifest named by title or reference, the value queues; an argument refusal still comes back when the egress filter faults.
- [x] 1.5 Check the Planning and declared field rules on store-owned saves. Share the dispatch route and bound writer arguments, and give the value refusal only when it is the commit’s first. Leave file-backed saves and edits by `item_id` to replay.
- [x] 1.6 Prove direct and busy store saves give the same first refusal. Cover an undeclared value, an explicit null status, guarded edits, and a disabled summary route. Prove a file-backed add queues and its replay gives the direct refusal.
- [x] 1.7 Bound every queue read and the declaration read by one shared budget, opening the queue and waiting for its locks included, give each statement only the time left, and treat an answer after it as unknown. Tests: a valid and a refused busy save each read no more of a longer queue; a revision open at the mark that applies during the read keeps the add queued; an ordinary save that applies during the read leaves the refusal; a store from before the record keeps a save behind its open revision queued, upgraded before the check or during its read, and its upgrade holds no stored save in memory; a revision that an earlier release queues keeps the add queued, also on a store whose earlier marker column defaults to 0; a queue that answers after the budget, or a locked queue whose open spends most of it, queues the save within the budget.
