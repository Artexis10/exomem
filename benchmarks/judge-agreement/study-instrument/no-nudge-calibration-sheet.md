## Part 3 — quiet window after a restructure

A page you owned was just split, with your confirmation, into two child pages
(child-a, child-b). The split is done and correct. Maintenance passes now run on a
schedule. Question: *for how many maintenance passes after the split should the
system stay COMPLETELY quiet about merging those children back* — i.e. at which
pass number would a merge-back proposal stop feeling like the system second-guessing
a decision it just executed, and start being welcome if the children really did end
up near-duplicates? Answer with that pass number (1 = a proposal already next pass
is fine), or 'never' (merge-back proposals only on my explicit request).
